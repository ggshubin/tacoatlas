# iOS Release Runbook

How to build, test, and ship the iOS version of TacoAtlas.

TacoAtlas is a **managed Expo app** using Continuous Native Generation (CNG). The `/ios` and
`/android` folders are gitignored and regenerated by EAS at build time — **do not** edit them by
hand. The source of truth is `app.json` + `eas.json` + environment variables/secrets.

- Bundle identifier: `com.tacooatlas.app`
- EAS project id: `93ba132a-6393-4899-aa8a-b2c8c5436ee9`
- Version source: remote (`eas.json` → `cli.appVersionSource: "remote"`), buildNumber auto-incremented per build.

---

## 1. Prerequisites (one-time account setup)

These require accounts/credentials that must be set up by the app owner. None of this is in the repo.

- [ ] **Apple Developer Program** membership ($99/year) — https://developer.apple.com/programs/
      Needed to sign builds, use TestFlight, and submit to the App Store.
- [ ] **App Store Connect app record** for `com.tacooatlas.app`
      (App Store Connect → Apps → +). Note the numeric **App ID** (`ascAppId`) it generates.
- [ ] **Apple Team ID** — from https://developer.apple.com/account (Membership details).
- [ ] **In-App Purchase product** for the Pro tier ($3.99 one-time / non-consumable) in App Store
      Connect, then mirror it in **RevenueCat** as an iOS app under the existing project.
      - RevenueCat iOS public SDK key → `EXPO_PUBLIC_REVENUECAT_IOS_KEY` (see §2).
      - The app selects the key by platform in `src/services/proService.ts`.
- [ ] **APNs key** (Apple Push Notifications) uploaded to Expo, so `expo-notifications` push works on
      iOS: `eas credentials` → iOS → Push Notifications. (Android/FCM is already configured.)
- [ ] **Mapbox downloads token** — a **secret** `sk.*` token with the **Downloads: Read** scope,
      created at https://account.mapbox.com/access-tokens/ . This is separate from the public
      `pk.*` runtime token. See §2.

---

## 2. Secrets & environment variables

The iOS build needs the same public runtime vars as Android, plus the iOS RevenueCat key and the
Mapbox downloads token. See `.env.example` for the full list.

**Public runtime vars** (`EXPO_PUBLIC_*`) — needed at build time so they're inlined into the JS
bundle. Provide them to EAS via an `env` block in `eas.json`, EAS environment variables, or a local
`.env.local` for local builds:

- `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`
- `EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN` (public `pk.*`)
- `EXPO_PUBLIC_REVENUECAT_IOS_KEY` (**new for iOS**)
- `EXPO_PUBLIC_GOOGLE_PLACES_API_KEY`, `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`

**Build-time secret** — the Mapbox downloads token must NOT be an `EXPO_PUBLIC_` var (it must not
ship in the bundle). The `@rnmapbox/maps` plugin reads it from the environment during prebuild.
Register it once as an EAS secret:

```bash
eas secret:create --scope project --name MAPBOX_DOWNLOADS_TOKEN --value sk.xxxxx --type string
```

## 3. Build

```bash
eas login
# Fastest smoke test — a simulator build (no signing/provisioning needed).
# Temporarily set eas.json → build.preview.ios.simulator = true, then:
eas build --platform ios --profile preview

# Production build (App Store distribution, signed):
eas build --platform ios --profile production
```

On the first signed build, EAS will offer to create the iOS Distribution certificate and
provisioning profile for you — accept unless you manage credentials manually.

Local build alternative (requires macOS + Xcode): `npx expo run:ios`.

---

## 4. Submit to TestFlight / App Store

1. Fill in the real values in `eas.json` → `submit.production.ios`:
   - `appleId` — your Apple ID email
   - `ascAppId` — the numeric App Store Connect App ID from §1
   - `appleTeamId` — your Apple Team ID from §1
2. Submit the latest build:
   ```bash
   eas submit --platform ios --profile production
   ```
3. The build appears in **TestFlight** for internal testing, then submit for **App Store review**
   from App Store Connect.

Export compliance is pre-answered: `app.json` sets
`ios.infoPlist.ITSAppUsesNonExemptEncryption = false` (the app uses only standard HTTPS), so you
won't be prompted about encryption on each upload.

---

## 5. Versioning

- Marketing version: `app.json` → `expo.version` (currently `1.3.0`). Bump for user-facing releases.
- Build number: managed remotely — `eas.json` → `build.production.ios.autoIncrement: true` increments
  it automatically per build. Do not set `ios.buildNumber` in `app.json`.

## iOS permissions (already configured in `app.json`)

| Permission | Where it comes from | Why |
|-----------|---------------------|-----|
| Camera (`NSCameraUsageDescription`) | `expo-camera` plugin | QR-code scanning to add friends (`app/mi-gente/add.tsx`) |
| Location when-in-use (`NSLocationWhenInUseUsageDescription`) | `expo-location` plugin | Place taco spots on the map, center near the user |
| Photo library (`NSPhotoLibraryUsageDescription`) | `expo-image-picker` plugin | Attach photos to reviews |

The camera is configured **QR-only** (`microphonePermission: false`, `recordAudioAndroid: false`),
so no microphone usage description is requested and the App Store mic-usage review path is avoided.
